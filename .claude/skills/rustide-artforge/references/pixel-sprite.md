# R2 · 像素小人

> 目标：给每个角色出**游戏可用的逐帧像素 sprite**，四方向 + 行走帧。
> 状态：**四方向静态已跑通**，行走帧待做。

## 官方规格（实测 + 调研）

| 项 | 值 | 依据 |
|---|---|---|
| Sprite 尺寸 | **32×32 起，角色约 40px 高** | 官方说法是 32×32 角色 sprite，环境 64×64+ |
| 视角 | **固定 3/4 俯视** | 实机截图，能看到一点头顶 |
| 动画 | **逐帧像素，不是骨骼**。走路顿、剪影对就行 | 官方画风说明原话 |
| 角色占比 | **相对场景很小，场景才是主角** | 同上 |

实机截图在 `assets/refs-gameplay/`。

## Sprite 的设计语言和立绘完全不同

从实机 NPC 抠图对比出来的：

| | 立绘 | 实机 sprite |
|---|---|---|
| 头身比 | 5 头身 | **约 3 头身**，头占 1/3 |
| 眼睛 | 纯黑椭圆 | **浅色眼白块 + 深色点** |
| 腿 | 两根细管 + 大靴 | **腿极短，几乎只剩靴子** |
| 色数 | 每部件 2 色 + 细节 | **每部件 2–3 色，无细节** |
| 手 | 连指块 | **一个小色块贴在身侧** |

> **sprite 是为 40px 重新设计的，不是把立绘缩小。**
> 实测：直接把立绘降采样到 32–48px，脸糊成一团、试剂瓶排变噪点，不可用。

## 管线

```
立绘（参考图）
  ↓  templates/SPRITE.txt          出「设计稿」：大尺寸、已按 sprite 语言简化、四方向
设计稿（1536×1024）
  ↓  checklists/spritecut.py       全分辨率抠图 → 装进格子 → 面积降采样 → 16 色量化
四张 32×48 透明底真像素图
```

```bash
python3 checklists/spritecut.py <设计稿.png> <输出目录> --cell 32x48 --colors 16
```

### ⚠️ 抠图必须在**全分辨率**做完再降采样

旧管线先缩到 40px 再按亮度阈值刷白底，这是错的：

- 缩完之后角色四周没有背景余量，边界泛洪进不去，
  下巴底下、腋下那些**封闭白洞永远刷不掉**（实测每帧残留 4–6 个纯白像素）
- 亮度阈值靠的是背景白 `(252,251,249)` 和骨白衣物 `(241,222,169)` 之间那 100 的缝，
  下一个穿白衬衫的角色就会被吃掉半件衣服

全分辨率下角色四周还有大片背景，一次边界泛洪就刷干净，**不需要任何阈值**。
实测设计稿里被角色包住的白块只有 28 个、最大 10px，全是衣物高光和眼神光，
没有真正的内嵌背景 —— 所以泛洪一次就够。

### ⚠️ 角色要**装进**格子，不是裁进格子

旧管线 `-resize x40` 之后直接裁到 24 宽，结果 12 帧的包围盒**全是满格 24×40**，
头发和肩膀顶死在画布壁上。必须等比缩放到内框（`32-4 × 48-4`），底部居中贴进透明画布。

**门禁**：切完断言每帧最外圈 1px 全透明，不合格直接报错。
这一步缺了，裁切帧才会一路走到 demo 里。

### 降采样用面积平均，不是最近邻

10 倍降采样时最近邻是 100 个像素里挑 1 个，**整只眼睛都可能丢掉**。
用面积平均（`Image.BOX`）保形好得多，随后的调色板量化会把抗锯齿削掉，仍是硬边真像素。
alpha 通道按 128 二值化。

色数实测：10 色太灰、24 色开始糊出中间调破坏平涂，**16 色最好**。

## ⚠️ 明度分离 —— 决定 sprite 成败的一条

第一版失败：藏青大衣 `#2F3542` 在 40px 下**和黑发糊成一团**，剪影读不出来。

对比实机 NPC，他们**每个相邻部件的明度差都拉得很开**（蓝衣 vs 肤色 vs 深发）。

修法写进模板：

> 头发、外套、皮肤、靴子各自处在**明显不同的明度**上。
> **立绘里很暗的颜色，到 sprite 版要提亮到中明度**，好和头发分开。

实测：把大衣从 `#2F3542` 提到 `#4A5568`，剪影立刻读得出来。

## 行走帧 ⚠️ 生图模型做不了动画帧

**试过了，不行。** `templates/WALKCYCLE.txt` 让它一张图出 4 方向 × 3 帧，结果：

| 做法 | 帧间像素差异 |
|---|---|
| AI 直接出 12 格，按网格切 | **60–78%** ❌ |
| 加锚点对齐（脚底贴地 + 水平居中） | 仍 60–78% ❌ |
| **程序化位移腿部** | **10–17%** ✅ |

原因：**gpt-image-2 把每一格当独立的图重画**——头发轮廓、大衣边缘每格都不一样，
不只是腿在动。放进游戏会疯狂抖动。

> 表情表能用一张图搞定，是因为它**允许**每格脸不同；
> 动画帧要求**除了腿以外一个像素都不能变**，这是完全不同的要求。

### 正确做法：从一张静态 sprite 程序化生成

```bash
python3 checklists/walkgen.py <静态sprite.png> <输出目录> <前缀>
```

四帧标准循环：接地 / 过渡 / 接地(反) / 过渡。播放顺序 `0 1 2 3`。

**v1 的三个硬伤（都改了）：**

| 问题 | v1 做法 | 后果 | v2 |
|---|---|---|---|
| 腿没真的动 | 先铺整张基底，再把位移的腿叠上去 | **原来的腿一直露在下面**，腿不是迈开只是变宽 1px | 腿整块抠走，在透明画布上重摆，腿离开处就是背景 |
| 没有起伏 | 只 3 帧，第 2 帧 `= base`，注释写着"身体高 1px"但代码没做 | 四方向里只有一个意外有起伏 | 过渡帧躯干真抬 1px，腰部用一条拉伸带补住接缝 |
| 只横移 | `dx=±1` | 40px 尺度下横移 1px 看不出来 | 抬腿（y 位移）为主，横移为辅 |

**腿区必须只取靴子**。按身高比例取（v1 的 28%）会切进大衣衣摆，
横移时把**衣服也劈成两半**，f2 帧腿间破一个洞。
v2 从底往上找宽度不超过底部两行均宽 1.35 倍的连续行 —— 自动落在靴子上。

两条腿在这个尺度下是连通的一整块，连通域分不开，所以按**谷底列**（腿间空隙）劈开。

默认参数：`--shift 1 --lift 1 --bob 1`。

### 左右方向用镜像

AI 出的「朝右」那一行常常画成朝左。2D 游戏本来就常用镜像，直接 `-flop` 更省更准。

### 输出格式

```
spritesheet.png   128×192  ——  4 列(帧) × 4 行(方向)，单帧 32×48
dir{0-3}.png              ——  四方向静态图
dir{0-3}_f{0-3}.png       ——  行走单帧散图
walk_dir{0-3}.gif         ——  预览
```

格子从 24×40 改到 **32×48**：24 宽装不下大发量 + 侧摆的胳膊，
实测四个方向全部顶墙。32×48 内框 28×44，四周留得出边距。

## 播放端：两条不做就一定难受

这两条不在美术里，在游戏代码里，但不做的话帧做得再好也白搭。

**1. 位置必须吸附到整数 sprite 像素**
内部位置用 sprite 像素为单位存小数，**渲染时 `Math.round(x) * 放大倍数`**。
直接把小数 CSS px 喂给 `translate()`，像素格永远对不齐 ——
浏览器每帧用不同的亚像素相位重新栅格化，有的像素列渲成 3px 宽、有的 5px，
而且每帧换一批。这就是那种"说不出来但很难受"的抖。

**2. 动画帧由走过的距离驱动，不由时间驱动**
`frame = floor(走过的距离 / 每帧步长) % 帧数`。
按时间换帧时，移动速度和步频是两个独立数字，一旦不匹配就是**脚在原地滑冰**。
按距离换帧走多快步子就多快，永远对得上。

`demo/index.html` 里两个开关可以直接开关这两条对比效果。

## 另一个坑：不要对每格单独 trim

按网格切之后如果对每格 `-trim`，每帧会按自己的包围盒对齐，**原点全不一样**，
游戏里角色会乱跳。要么按固定网格切不 trim，要么用
`checklists/align.py` 按「脚底贴地 + 水平居中」统一锚点。
